# PI Bot 0.3.90：可靠续跑与待处理

日期：2026-11-03（Asia/Shanghai）。用途：0.3.90 发布说明。已完成本地自动测试及安装包校验；本轮尚未完成真实 PI Desktop 与真实模型联调验收。插件市场需单独上传更新。

## 这批完成的内容

1. **先保存，再做事**。问题回答、队友结果转交、任务续跑、手动恢复及群派发采用持久准入；写入失败时撤回本次任务及关联，不启动原生执行。
2. **多人任务自动接回**。群成员全部结束且没有待回答问题后，总控在原群规划会话中回收结果。只为原请求确有必要的后续步骤继续派发，最多两批。普通问候不增加回收回合；原有任务总结与批次回收共用一个出口。
3. **不确定时先核对**。保存领取编号防重复；原生提交回执丢失、重启中断、主动停止及执行记录缺失进入待处理，不盲目重发。失败不等于成功，用户未回答的问题也不等于已完成。
4. **集中待处理**。用户问题、交互卡片、经验建议、密钥需求、原生审批跳转、错误和已结束回合汇总到设置中。列表每页 20 条，不为打开或刷新调用模型；大段正文仍在原聊天/会话里查看。
5. **状态冲突保护**。团队数据文件只有一个插件写入者；检测到外部修改时保留最后提交的插件版本及外部版本，暂停自动派发。用户在待处理查看副本位置，两次点击确认保留当前插件数据。恢复后未完成任务需核对、自动化暂停，不自动合并或复活外部旧名单。
6. **稳定性细节**。记忆复查逐项过滤不合法建议、保留有效项及无正文诊断；真正的 I/O 失败仍保留复查进度。带引号名称兼容、群公告上限明确提示、群设置失败局部回滚；空闲检查降频、历史用量分批补扫。长群规划资料复用完整附件路径。
7. **就近的群聊控制**。群内有工作或待继续交接时，原发送键变成方块停止键，不另加按钮；无需先打开群详情。停止中保留按钮并禁用重复点击、即时显示状态，出错后可重试。输入草稿保留，其他群及私聊不受此按钮影响；结束后恢复发送箭头。
8. **正常长任务不停在固定次数**。移除群内文字 @ 交接的固定上限与次数设置，旧版保存的 relayLimit 不再限制执行。只有连续六次无工具操作的简短确认或同一 Bot 重复内容才暂停，保留待办；点击输入框上方继续或发新消息可接续。有新内容或工具工作会重置空转计数。这是本插件按自身任务结构实现的保护，不替换现有权限或原生运行框架。“工作经验”是栏目标题，复盘经验按钮紧邻标题。

## 在哪看

- PI Bot 左下角头像 → 插件设置 → **待处理**：需要我处理 / 运行异常 / 已完成待查看。
- 群聊运行中 → **原发送键位置的方块**：停止本群；群详情的全部停止入口也保留。
- 群详情 → **成员区域前的空转保护说明**；Bot 私聊底部的工作经验标题旁可点击复盘经验。
- 运行异常 → **打开原聊天**、**打开原生会话** 或 **核对与恢复**。
- 任务恢复中心仍可从 设置 → 关于 PI Bot → PI 扩展 进入。
- 群聊发送实际任务，成员交回后会出现总控的“正在回收成员结果…”及逐步更新；不新增必须开启的开关。
- 数据冲突时待处理列出双方副本路径；请先核对，再决定是否保留当前数据。此操作不是自动智能合并。

## 使用与边界

- 先安装新版本并重载 PI Bot 插件或重启 PI Desktop。建议更新前导出个人备份；旧版安装包保留。
- 结果回收使用管理员配置的模型，计入现有用量。界面刷新和普通问候不会因此多一次模型回收。
- 任务提交、磁盘保存和外部工具不是跨系统事务；保存/去重不保证邮件、发布等外部操作绝对只发生一次。结果未知时应打开原生会话检查。
- 原生审批必须在 PI Desktop 中完成，待处理页面不能代替或绕过批准。显示“已结束”或点击“已查看”都不等于成果已验收。
- 文件冲突保护不能阻止不遵循本锁的外部程序写文件，也不承诺系统断电时的 fsync 级保证；发现冲突后保留副本而不是自动拼接权限或旧名单。
- 本批对应可靠执行、异常入口和独立稳定性修复。团队模板、成果自动检查、调度历史增强、文件夹触发及更多宿主集成留待后续分批；浏览器扩展仍暂缓。
- 保留 DS Bot 来源说明与 Apache-2.0 许可证；研究对照资料保存在公开仓库外。
