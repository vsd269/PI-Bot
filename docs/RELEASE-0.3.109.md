# PI Bot 0.3.109

基于 0.3.108 的应用连接启动修复版，插件 ID 继续使用 `local.pi-bot`。

## 修复的问题

此前，应用账号列表与侧栏应用图标仅在打开“连接应用”窗口时更新。重启 PI Desktop 或切换回 PI Bot 后，界面无法主动恢复已有连接的显示，容易被误认为之前的授权未加载。保存的项目密钥、账号标识和 Bot 分配并未因此丢失。

## 更新内容

- 插件启动后，在后台读取本机加密库中的原项目配置，并检查已连接账号。无需点击“连接应用”，无需重复填写项目密钥或重新分配 Bot。
- 启动检查不等待应用目录、分类或第三方网络返回，不阻塞聊天界面及其他任务。原生界面与 PI Bot 间切换不会重建授权会话。
- 应用状态随现有会话快照同步到 PI Bot。侧栏自动显示已保存／已检查的应用图标，悬停说明区分正在检查、已连接和检查失败。
- 进入应用窗口时复用一分钟内的成功检查结果；启动检查尚未完成时，共用同一个请求，避免重复访问服务。
- 后台每五分钟更新连接状态。临时网络失败后按 15 秒、30 秒、60 秒等间隔退避重试，最长间隔五分钟；密钥或权限错误降低为五分钟检查一次。
- 自动重试仅用于读取账号状态，不自动创建新授权、不自动调用工具、不重复执行外部写入操作。失效授权仍需用户处理。
- 保留每个 Bot 的既有应用分配，向其任务上下文补充获分配账号及工具发现入口；不打开应用窗口也能发现对应工具。调用时继续核对 Bot 授权和账号有效性。
- 清除、更换项目或导入加密配置后，旧缓存与旧请求不会覆盖新配置；插件卸载时停止后台定时器并取消未完成的账号检查。
- 不把密钥、授权会话标识或账号令牌放入公开连接状态、聊天快照、普通备份或安装包。

## 更新方法

1. 在 PI Desktop 的插件页面导入 `local.pi-bot-0.3.109.piplug`。
2. 使用相同插件 ID 更新，不要删除插件数据。安装后重载插件或重启 PI Desktop。
3. 进入 PI Bot，后台会自动检查已有应用连接；不必先打开“连接应用”窗口。

跨电脑安装仍使用同一个插件包。Bot 设置与聊天记录使用原有备份／恢复功能；项目密钥等凭据使用密码加密的迁移导出／导入功能。单独复制插件代码不包含个人账号凭据。

## 验证范围

使用隔离配置与模拟应用服务验证启动恢复、未打开窗口时的工具发现、缓存复用、网络退避、配置切换、权限隔离和停止清理；另验证完整 PI Bot 界面的侧栏恢复、应用窗口和宿主加载／安装。

未访问用户真实的 Composio 项目、未重新授权真实账号、未调用付费模型或外部写入工具。真实第三方账号若已过期或项目服务不可用，仍需按应用窗口中的具体错误处理。
