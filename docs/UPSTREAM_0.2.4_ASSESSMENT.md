## 1. 群聊一键停止

上游 `ds-bot/src/host/groups.js:915-944` 先停止群的协调回合，再停止各成员在本群的工作。这样不会误停同一个 Bot 在私聊或其他群里的工作。

PI Bot `src/team.js:701-706` 有任务取消，`renderer/app.mjs:524-529` 有逐成员停止，但管理员规划是另一条执行路径，见 `src/team.js:401-458`；发送还会进入群的串行链，见 `:395-399`。

因此不能只循环点击已有的成员停止。适配至少需要：

- 先使本群当前协调回合失效，再取消本群任务。
- 处理已排队消息、正在启动的任务和正在等待交接的任务。
- 阻止晚到的规划结果、回调和自动交接在停止后继续派发。
- 保留其他群与私聊的工作；停止不代表撤销已发生的文件修改或外部操作。

验收应覆盖规划中、排队中、运行中、等待交接及晚到结果；这是新功能的验收要求，本次尚未执行这些迁移测试。

## 2. 工作经验提案：保存为 Skill

上游 `ds-bot/src/host/learning.js` 的做法是后台复盘完成的长任务，提出一个可复用 Skill，再由用户批准。不是每次对话都自动生成，更不是自动修改模型本身。

默认门槛见 `:15-30`：任务至少 3 分钟、团队空闲约 10 分钟、复盘间隔约 12 小时，并限制读取文本、学习数量和拒绝记录。复盘调用模型，会有额外模型用量。

批准/拒绝见 `:630-648`；保存与同名冲突检查见 `:691-716`。可以复用 PI Bot 现有能力库，补充“待确认提案”，显示理由、内容、接受和拒绝。应保留去重、敏感信息检查、数量限制，以及 Bot 被删除或 Skill 已变化时的过期处理。

## 3. 项目规则提案：更新 AGENTS.md

这是与 Skill 不同的一项能力：从项目工作中提出后续应遵守的规则，例如构建方式、目录约定和验证步骤。

上游 `learning.js:652-688` 不直接盲目覆盖文件：按路径串行应用，核对实际工作目录，只写该目录的 AGENTS.md，并在替换前检查原文件存在状态及内容哈希，防止覆盖用户后来修改的内容。

PI 适配应展示修改前后差异，由用户批准后保存；文件已经变化时要求重新生成提案。应提供关闭后台复盘的设置，并明确额外用量。

## 4. 侧栏：已有基础，只迁移差额

PI Bot 已有：

- `renderer/app.mjs:65-71`：拖动宽度，220–420 px，保存宽度。
- `renderer/app.mjs:105-107`：折叠成头像栏，保存折叠状态。
- `renderer/style.css:331-349`：头像栏样式。
- `renderer/app.mjs:152`：Bot/群名称完整 title。

上游 `ds-bot/src/client/frame-layout.js:9-58` 把聊天区最小宽度、侧栏宽度、头像栏、右面板和浮层统一决策。值得补的是窄窗优先收起右面板、拖至阈值吸附成头像栏、避免聊天内容挤压。不要照搬 DSH 原生壳的 DOM/portal 挂接，也不必强制把 PI 现有头像栏宽度改成上游的 88 px。

## 5. Office：轻量工具可移植，完整环境另算

上游分为两层：

1. 插件侧：`ds-bot/src/host/office-skills.js:35-88` 注册 office / office-tools 两个 Skill，并定位可用的独立 Node；`ds-bot/office.js` 是约 310 KiB 的打包工具。
2. 独立桌面应用：另带 Python、文档处理库、Node、LibreOffice Kit 等运行环境。详见 `docs/plans/2026-10-27-office-documents.md`。

轻量 CLI 的真实命令在 `ds-bot/src/office/cli.js:21-41`：

- Office 包解包、重新打包、结构检查和部分修复。
- Word 读取、字段检查和定点编辑。
- PPT 结构清单、布局检查、页面重排/复制和清理。
- Excel 工作簿清单、单元格值及公式读取；独立 CLI 没有专门的 Excel 高层编辑或公式重算命令。

通过 XML 解包编辑再打包可以改文档结构，但不能把这称为完整的 Excel 计算引擎。创建复杂文档、渲染预览、导出 PDF 和重算表格要按实际运行环境另外适配和验证。

建议先接入小工具和 PI 的 Skill/工具适配层，检测运行环境、明确可用功能，默认输出新文件。需要完整环境时再做可选安装，不把上游独立桌面的大套运行环境直接塞进插件。用户现有 API 密钥、模型、聊天记录无需因此变更。

## 6. 私密 Bot：先验证执行边界

上游 `ds-bot/src/host/privacy.js:1-4` 明确说明这不是操作系统级隔离：它拦截自身工具和文件/命令显式路径，Shell 仍可能访问当前系统账号有权访问的文件。

其关键依赖是 `:298-305` 的 `tools/execute` 执行前拦截，再配合会话与子任务归属、文件真实路径/符号链接、团队历史和消息分享审批。

还有产品限制，见 `:321-348`：主 Bot 不能设为私密，必须有独立工作目录，先退出所有群，目录不能与其他 Bot、群或团队目录重叠。删除后的私密归档也不能直接失去保护，见 `:30-32`、`:354-361`。

缓存 PI Desktop 官方 SDK 源码 `output/execution-engine-research/PI-Desktop-evidence/packages/plugin-sdk/src/index.ts:151-157` 声明可通过 `agent.extension` 权限贡献进程内 ExtensionAPI 模块。因此不能简单断言 PI 没有扩展入口。但本次未在实际安装的 PI Desktop 中验证拦截覆盖范围、会话/子任务身份、原生工具和审批流程。

迁移前应先做这些兼容性验证；只有 PI Bot 自有工具过滤时，应如实标注有限保护，不能宣传所有文件读取都已隔离。需要更强保证时，还要宿主沙箱或系统访问控制。

## 7. Deep View 与其他修复

上游 `ds-bot/test/show-view-scope.test.js` 验证 Bot 会话内的 show_view 覆盖全局定义，其他会话保留全局工具；该行为建立在 DSH 的作用域工具注册机制上。

PI Bot 已通过 `src/views.js`、`src/upstream/views.cjs` 和 `renderer/view-widgets.mjs` 提供视图。公共包替换并非直接新增一项用户能力。应先验证 PI 的工具注册范围、重名和打包兼容性，再决定是否同步；本次没有证据证明 PI 当前存在同等冲突。

上游的无文本通知读取 bug，在 PI 的对应分页路径中已有处理：`src/tools.js` → `src/history.js` → `src/coordination.js:10-23`，对缺省 text 使用 `String(line.text || '')`。本次实际运行 Node 断言，普通读取、关键词搜索、按通知 ID 定位均通过。这个结果仅证明该读取路径，不代替整个群聊系统测试。

Windows 安装目录可写性检查和 DeepSeek Harness 0.2.1-rc.4 更新属于上游宿主/安装器；PI Bot 没有对应的同款独立安装器，不能直接套用。

## 建议实施顺序与边界

1. 群聊一键停止与窄窗口布局补强，先做取消时序及布局回归测试。
2. 统一提案审批模块，分别接入 Skill 和 AGENTS.md；有开关、用量提示、预览及冲突检查。
3. Office 轻量 CLI、能力路由和运行环境检测，再按需要增加可选渲染/计算环境。
4. 在实际 PI Desktop 验证扩展拦截和审批后，决定私密 Bot 的实现与对外说明。
5. Deep View 按确切兼容性收益决定，不为追版本重写已有视图系统。

迁移时保留 Apache-2.0 上游版权和归属；保持插件 ID `local.pi-bot`、已有数据迁移、原生权限确认与消息流式显示。上述实施项目前均为建议，尚未迁移。
