# PI Bot 执行可靠性评估

评估日期：2026-10-30（Asia/Shanghai）。基线：PI Bot 0.3.86。本文件记录 PI Bot 自身的执行机制、已修复范围与边界。

## 现状与本次改动

| 环节 | 原有机制 | 本次补充 |
| --- | --- | --- |
| 任务派发 | message_bot 请求编号去重、执行者任务队列 | 带编号的执行者派发将任务、父子关联与接收确认一起保存，保存成功后才启动 |
| 重启恢复 | 持久任务与原生会话核对 | 根据请求编号和预留任务编号核对；结果不明时保留中断状态，不静默重派 |
| 状态追踪 | jobs、handoffs 与工具记录 | 最近 512 条执行状态变化；恢复中心按需读取，不记录正文或密钥 |
| 派发查询 | 自动结果回交 | check_delegation 只读查询发起者自己的派发 |
| 现有交互 | 私聊/群聊流式更新、串并行和增量同步 | 保留现有呈现链路，不额外插入模型规划或审核回合 |

## 保留的能力

继续复用现有 jobs、handoffs、team.json、长期记忆、能力库、用量统计和 PI 原生会话；不引入新数据库、独立常驻服务或第二套消息系统。带编号执行者派发以外的管理员规划和旧无编号入口继续保留兼容机制。

## 需要区分的边界

- 接收去重不保证邮件、发布或文件写入等外部效果只发生一次。
- 任务状态“完成”不代表文件内容或产品结果已经通过独立验收。
- 恢复中心核对、继续和重试不等于任意工具的精确断点续跑。
- 请求中止不能撤销已经完成的外部修改；原生工具权限仍由 PI Desktop 控制。
- 工作目录不同不等于系统沙箱；宿主退出后，本地定时任务不会继续运行。
- 当前没有完整任务依赖图、自动成果验收器、永久事件仓库或精确费用硬预算。

## 验证

首批执行补丁的本地测试见 [测试记录](EXECUTION_ENGINE_TEST_REPORT.md)；后续计划见 [阶段计划](EXECUTION_ENGINE_PLAN.md)。测试使用实际 PI Bot 模块、临时文件和模拟宿主，不代表所有真实模型与操作系统环境均已验证。

PI Bot 既有 DS Bot 来源、Apache-2.0 和随包依赖许可证继续保留。本批执行可靠性补丁基于现有 PI Bot 结构实现，不替换宿主运行时。
