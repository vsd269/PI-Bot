# DeepSeek-Bot 0.2.0 本地源码对照

检查日期：2026-10-21（北京时间）。目标：PI Bot 0.3.82，基于 0.3.81。

## 对照来源

- 用户提供的 `E:\安装包\DeepSeek-Bot\0.2.0\DeepSeek-Bot-main.zip`，解压目录为 `_src\DeepSeek-Bot-main`。
- 该目录的 `更新内容.txt` 是空文件，实际版本说明见解压源码的 `CHANGELOG.md`，0.2.0 条目日期为 2026-10-21。
- 本次依据本地下载内容检查，没有独立确认 GitHub 发布时刻，也不将上游自己的修复说明当成 PI Bot 已通过的测试。

## 本版落实的修复

原生侧栏的 PI Bot 入口原来固定在第二列。左侧 Our Free Model 插件停用时，入口仍留在第二列，与空出的第一列一起造成视觉空洞。

`renderer/sidebar-entry.mjs` 现在从左侧第一个实际位置开始查找空位，依据可见的兼容插件入口排列；响应相邻入口加载、移除和可见性变化。`renderer/entry.mjs` 不再传入固定列号。

两个插件旧版本共用一行垂直占位。本版保留归属标记，只在最后一个归属移除时释放这行，防止清理 PI Bot 时删除其他插件所需的空间。没有改写 Our Free Model 的代码、宿主按钮或用户数据。

验证包括两种加载顺序、停用后自动补位、重新启用不重叠、隐藏/恢复、切换 Bot 模式、卸载后另一个入口继续可点击、全部卸载后无残留、长会话列表不被覆盖、无持续 observer 循环，以及宿主布局缺失时的备用位置。

## 稳定性修复怎样参考

- **慢机器启动、待回答卡片和权限选择回退**：当前已有异步 activation、持久化问题及偏好保存保护，但实现路径与上游不同。本版共 110 项回归测试，不表示上游每个复现场景都已覆盖。
- **群消息即时显示**：当前管理员规划已有 `nativePlan`/`partialPlanReply` 预览和状态增量同步；不能用上游 DSH 的消息协议整体替换 PI 的原生协议。本次没有改动该链路。
- **Windows 写文件争用、重载时保留待发消息、缓存用量水位、带方括号的名称、特殊 ID**：应按 PI 的存储/队列/用量/名称匹配分别建立复现后再修。上游列出的 bug 不等于本插件已确认存在或已经根治。
- **特殊 ID**：PI Bot 多处以数组查找 Bot/群，而上游部分代码使用对象索引；不要盲目复制上游补丁，也不能只检查一处就宣布所有入口安全。

## 不能原样搬入的内容

上游 0.2.0 新增的独立 Windows/macOS 桌面壳、DeepSeek 登录、自己的自动安装更新、DSH 数据目录和 Docker 发布，属于其客户端与运行时。PI Bot 是 PI Desktop 插件，应接入 PI 的公开接口，不能通过复制上游壳实现这些能力。

上游的 `shadow('sidebar.footer.action', ...)` 是 DSH 内部挂载点；本地 PI SDK 中未找到等价的公开侧栏入口 slot。本版继续使用 PI 的独立 layer，保留现有兼容挂载。包校验和隔离原生安装测试不代表插件市场审核或真实账号运行测试已经通过。
